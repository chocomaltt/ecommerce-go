One milestone. One proof.

Do these in order. Do not start Kafka, payment, or another service before the current milestone’s proof passes.

0. Foundation — done

Workspace modules, Buf contracts, Ory Compose, local CA and workload certificates.

./deployments/compose/certs/generate.sh
cd common-rpc && buf generate && buf lint

Proof: generated Go code exists and Buf lint passes.

1. Auth vertical slice — done

Client → Edge → Identity → Kratos and Edge → Order. Read the dedicated guide before changing this slice.

Proof: `GET /auth/order-caller` returns the authenticated actor only with a valid Kratos session, mTLS Edge certificate, and valid Identity assertion.

2. Replace demo Order RPC

Keep the same interceptor. Add a real `GetOrder` RPC and an Order repository port. In the use case, load the order then require order.CustomerID == actor.UserID. Never put that rule in Edge.

Definition of done: owner gets order; different authenticated user gets PermissionDenied; direct non-mTLS caller fails.

3. Catalog → Order checkout read

Add Catalog contract and outbound port in Order. Order calls Catalog synchronously only to obtain sellable product facts, then stores a snapshot.

Definition of done: checkout rejects unpublished/missing SKU; accepted order contains immutable item name/price snapshot.

4. Persistence

Add service-owned PostgreSQL repositories and migrations. No cross-service database access. Introduce an outbox in the same transaction as order state changes.

Definition of done: restart-safe order state and one durable outbox record per emitted fact.

5. Inventory, payment, notifications

Only now add Kafka commands/events, idempotent consumers, saga states, and compensation. Build one workflow transition at a time.

Definition of done: a failed reservation/payment leaves an observable, recoverable order state.

Every change checklist

  1. Write/adjust proto first if another service needs the capability.
  2. Define inbound/outbound port inside the owning service.
  3. Implement use case; it must not import transport or database package.
  4. Implement adapter and transport mapping.
  5. Add unit test near the unit; add integration/E2E test only when a real boundary is crossed.
  6. Run module tests, race detector, vet, and Buf lint.
