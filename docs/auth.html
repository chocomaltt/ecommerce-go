Authentication without confused trust boundaries.

This guide documents the implemented pattern end to end — threat model, contracts, code, tests, runbook, and production hardening. Read it before touching auth.

1. Problem and threat model

An ecommerce API has two distinct identities that must never be conflated:

IdentityWhoProvesMechanism
User identityKratos account“This request acts on behalf of user X”Signed actor assertion
Service identityCalling service“This caller is edge-api, not an impostor”mTLS workload certificate

Trust boundaries:

Internet ──► edge-api ──mTLS──► identity-service ──private HTTP──► Kratos
                        │
                        └────mTLS──► order-service ──► domain use cases
ThreatMitigation
Impersonate Edge from inside the networkTLS 1.3 mutual TLS; server verifies client certificate chain and SAN equals edge-api.internal per RPC via interceptor.
Replay a stolen user tokenAssertions are short-lived (60 s), signed, and bound to the target audience; session still validated against Kratos on every request.
Forge a user assertionEd25519 signature over header.payload; private key exists only inside identity-service.
Replay an assertion minted for another serviceaud claim must equal the receiving service; Order rejects everything else.
Tamper with x-user-id style headersHeaders are never trusted; only the verified assertion in Authorization plus the verified mTLS peer produce actor context.
Token theft at rest in the browserProduction browser flows must use HttpOnly/Secure/SameSite cookies; bearer tokens are for APIs/Bruno only (see §11).
Identity service reachable by any callerPrivate gRPC port, mTLS, and AuthorizeCaller ACL rejecting every non-Edge SAN.
Never forward the Kratos session token past Identity. Never accept x-user-id as authority. Private networking alone is not authentication.

2. Components and responsibilities

ComponentOwnsMust not own
KratosCredentials, identities, sessions, recovery, verification, MFA.Application authorization or service-to-service trust.
identity-serviceAuth orchestration; resolve Kratos session; issue internal actor assertions.Passwords or persistent Ory session state.
edge-apiPublic HTTP mapping; invoke private gRPC ports.Kratos adapters or domain authorization.
order-serviceVerify trusted actor; ownership and business rules.Calling Kratos or trusting user-supplied headers.

Hydra is not part of this design. Internal machine-to-machine trust uses workload mTLS, and user identity uses Kratos sessions — no OAuth2 authorization server is needed for first-party flows. Reintroduce Hydra only when third-party OAuth2/OIDC clients are a requirement.

3. Request flow (sequence)

1. Client      Edge: Authorization: Bearer <Kratos session token>
2. Edge        Identity: ResolveSession(token, audience="order-service")   [mTLS]
3. Identity    Kratos: GET /sessions/whoami                                [private HTTP]
4. Identity    Edge: user + Ed25519 signed actor assertion (TTL 60 s)      [mTLS]
5. Edge        Order: mTLS + Authorization: Bearer <actor assertion>
6. Order: verify Edge certificate → verify JWT signature → iss → aud → exp
7. Order use case: actor from context; enforce ownership/business authorization

What each hop proves:

  1. Client proves it holds a live Kratos session.
  2. Edge proves its workload identity to Identity; Identity never sees the client again.
  3. Identity re-validates the session with Kratos on every call — no cached trust.
  4. Identity returns user data plus a fresh, target-bound assertion. Edge cannot mint or alter it.
  5. Edge proves its workload identity to Order and forwards the assertion as the user credential.
  6. Order authenticates the caller twice: certificate (service) and assertion (user).
  7. Domain code receives port.Actor{UserID, Email, CallerService} from context and applies ownership checks.

5. Actor assertion specification

A JWT (EdDSA/Ed25519), signed by identity-service, carrying verified user claims.

ClaimExampleMeaning
subkratos identity UUIDThe Kratos identity this request acts for.
emailuser@example.comDisplay/audit identity; never used for authorization.
audorder-serviceSingle target service. Prevents cross-service replay.
issidentity-serviceVerifier must enforce the configured issuer.
iat / expunix seconds, 60 s apartShort lifetime limits replay window.
jtirandom 128-bitUniqueness; future revocation/audit reference.

Issuer (identity-service) — internal/adapter/assertion/issuer.go:

type claims struct {
  Subject   string `json:"sub"`
  Email     string `json:"email"`
  Audience  string `json:"aud"`
  Issuer    string `json:"iss"`
  IssuedAt  int64  `json:"iat"`
  ExpiresAt int64  `json:"exp"`
  ID        string `json:"jti"`
}

func (i *Issuer) Issue(ctx context.Context, actor port.Actor) (string, error) {
  if err := ctx.Err(); err != nil { return "", err }
  if actor.Subject == "" || actor.Audience == "" {
    return "", fmt.Errorf("actor subject and audience are required")
  }
  now := time.Now()
  id := make([]byte, 16)
  if _, err := rand.Read(id); err != nil { return "", err }
  header := base64.RawURLEncoding.EncodeToString([]byte(`{"alg":"EdDSA","typ":"JWT"}`))
  payload, _ := json.Marshal(claims{Subject: actor.Subject, Email: actor.Email,
    Audience: actor.Audience, Issuer: i.issuer,
    IssuedAt: now.Unix(), ExpiresAt: now.Add(i.ttl).Unix(),
    ID: base64.RawURLEncoding.EncodeToString(id)})
  body := base64.RawURLEncoding.EncodeToString(payload)
  signedPayload := header + "." + body
  signature := ed25519.Sign(i.privateKey, []byte(signedPayload))
  return signedPayload + "." + base64.RawURLEncoding.EncodeToString(signature), nil
}

Verifier (order-service) — internal/identity/assertion.go: split into 3 segments, decode signature, ed25519.Verify over header.payload, then decode claims and reject unless sub != "", iss == configured, aud == configured, and now < exp.

6.1 Auth use case — identity-service/internal/usecase/auth/service.go

func (s *Service) ResolveSession(ctx context.Context, token, audience string) (User, string, error) {
  if token == "" || audience == "" {
    return User{}, "", ErrInvalidRequest
  }
  user, err := s.resolve(ctx, token)        // Kratos Whoami
  if err != nil { return User{}, "", err }
  assertion, err := s.assertions.Issue(ctx, port.Actor{
    Subject:  user.ID,
    Email:    user.Email,
    Audience: audience,
  })
  if err != nil { return User{}, "", err }
  return user, assertion, nil
}

6.2 Edge middleware — edge-api/internal/interface/http/middleware/auth.go

func (m *AuthMiddleware) EnsureAuthenticated() gin.HandlerFunc {
  return func(c *gin.Context) {
    token, ok := bearer(c.GetHeader("Authorization"))
    if !ok {
      response.Unauthorized(c, "unauthorized", nil)
      c.Abort(); return
    }
    session, err := m.identity.ResolveSession(c.Request.Context(), token, m.audience)
    if err != nil {
      response.Unauthorized(c, "unauthorized", nil)
      c.Abort(); return
    }
    c.Set(sessionKey, session)   // port.Session{User, ActorAssertion}
    c.Next()
  }
}

6.3 Edge forwards the assertion — edge-api/internal/adapter/ordergrpc/order.go

func (c *Client) GetCaller(ctx context.Context, assertion string) (port.Caller, error) {
  ctx = metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer "+assertion)
  response, err := c.service.GetCaller(ctx, &orderv1.GetCallerRequest{})
  if err != nil { return port.Caller{}, fmt.Errorf("get caller from order-service: %w", err) }
  return port.Caller{UserID: response.UserId, Email: response.Email, Service: response.CallerService}, nil
}

6.4 Order authenticates the request — order-service/internal/interface/grpc/server.go

func Authenticate(expected string, verifier port.ActorVerifier, contexts port.Context) grpc.UnaryServerInterceptor {
  return func(ctx context.Context, request any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
    peer, ok := peer.FromContext(ctx)
    if !ok { return nil, status.Error(codes.Unauthenticated, "missing peer") }

    tlsInfo, ok := peer.AuthInfo.(credentials.TLSInfo)
    if !ok || len(tlsInfo.State.VerifiedChains) == 0 || len(tlsInfo.State.VerifiedChains[0]) == 0 {
      return nil, status.Error(codes.Unauthenticated, "unverified client certificate")
    }
    if err := tlsInfo.State.VerifiedChains[0][0].VerifyHostname(expected); err != nil {
      return nil, status.Error(codes.PermissionDenied, "caller not authorized")
    }

    metadata, ok := metadata.FromIncomingContext(ctx)
    if !ok { return nil, status.Error(codes.Unauthenticated, "missing actor assertion") }
    values := metadata.Get("authorization")
    if len(values) != 1 || !strings.HasPrefix(values[0], "Bearer ") {
      return nil, status.Error(codes.Unauthenticated, "missing actor assertion")
    }
    actor, err := verifier.Verify(strings.TrimPrefix(values[0], "Bearer "))
    if err != nil { return nil, status.Error(codes.Unauthenticated, "invalid actor assertion") }

    actor.CallerService = "edge-api"
    return handler(contexts.WithActor(ctx, actor), request)
  }
}

6.5 Domain code reads the actor — order-service/internal/usecase/identity/service.go

func (s *Service) Caller(ctx context.Context) (port.Actor, error) {
  actor, ok := s.context.Actor(ctx)
  if !ok { return port.Actor{}, ErrMissingActor }
  return actor, nil
}

Real use cases receive port.Actor and enforce ownership, e.g. order.CustomerID == actor.UserID → PermissionDenied otherwise.

7. mTLS and workload identity

All internal gRPC requires TLS 1.3 with client certificate verification:

  • Identity server: ClientAuth: tls.RequireAndVerifyClientCert, trusts ca.crt, then AuthorizeCaller("edge-api.internal") on every RPC.
  • Order server: same TLS config, plus the assertion check described in §6.4.
  • Edge client: presents edge-api.crt/key, verifies server against the CA with ServerName: <service>.internal.

9. Adding a new protected RPC

Step A — contract

Add the RPC/message to the owning service’s proto. Generate and lint:

cd common-rpc
buf generate && buf lint

Step B — domain use case

In the owner service, add a use case that receives the actor from context and enforces ownership/state rules. Example:

func (s *OrderUseCases) Get(ctx context.Context, orderID string) (Order, error) {
  actor, err := s.identity.Caller(ctx)
  if err != nil { return Order{}, err }
  order, err := s.orders.Find(ctx, orderID)
  if err != nil { return Order{}, err }
  if order.CustomerID != actor.UserID {
    return Order{}, ErrForbidden
  }
  return order, nil
}

Step C — inbound gRPC adapter

Register the handler. Authentication stays in the interceptor; the handler only maps protobuf request → use case input → protobuf response and maps domain errors to gRPC codes.

Step D — Edge outbound port and adapter

Add a capability to apps/edge-api/internal/port and implement it in a gRPC adapter. Forward the assertion received from Identity; never reconstruct identity data.

Step E — Edge HTTP handler

Read the session from Gin context (set by middleware), call the outbound port, map expected errors to HTTP. No business rules in Edge.

Step F — prove it

Unit-test the use-case branch (owner vs non-owner). Add integration coverage only for real gRPC/mTLS/assertion behavior. Add E2E only with services and Ory running.

12. Browser / frontend guidance

ContextTransport
API clients, Bruno, tests, M2MAuthorization: Bearer <session_token> (current API).
Browser SPA (production)Change Edge to set the Kratos session as a cookie: HttpOnly, Secure, SameSite=Lax. Middleware then reads the cookie instead of the header. Never store the session token in localStorage.

Whatever the transport, the internal flow is unchanged: Edge → Identity → Kratos, then target-bound assertion to Order. Cookies never travel beyond Edge.

13. Production hardening

  1. Certificate rotation — replace static dev certs with short-lived workload certificates from SPIFFE/SPIRE (or a private CA with a rotation job). Keep per-RPC caller ACLs.
  2. Signing key management — the Ed25519 actor key stays in identity-service (secret manager or KMS-backed file); distribute only the public key. Rotate on a schedule and support multiple active keys for graceful transition.
  3. Session policy — Kratos session lifetime, absolute expiry, and revocation; logout must invalidate server-side.
  4. Rate limiting — coarse limits at Traefik, identity-aware policy at Edge; protect login/register against credential stuffing.
  5. Audit — log actor sub, aud, jti, and caller SAN for every protected RPC; redact tokens and passwords everywhere.

14. Design decisions (why)

DecisionWhy
Auth orchestration in identity-service, not EdgeEdge stays a thin gateway; only one service knows Kratos HTTP semantics; Ory adapters are isolated behind ports.
Signed assertions instead of x-user-idHeaders are mutable and only safe under complete caller trust; assertions add signature, issuer, audience, and expiry.
Target-bound aud, 60 s TTLLimits replay blast radius and prevents a token minted for one service being accepted by another.
Edge cannot mint assertionsThe signing key lives only in identity-service; a compromised Edge cannot forge users.
Domain services verify, don’t re-fetchOrder does not call Kratos; it trusts the verified assertion, then applies its own ownership/business rules.
No HydraFirst-party flows need neither OAuth2 client registry nor consent; mTLS covers service identity. Add Ory Hydra only when third-party OAuth2/OIDC clients appear.
