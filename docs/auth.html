Authentication without confused trust boundaries.

This guide documents the implemented pattern and the exact order to extend it. Read this file before touching auth.

1. Goal and non-goals

ComponentOwnsMust not own
KratosCredentials, identities, sessions, MFA/recovery.Application authorization or service-to-service trust.
HydraOAuth2/OIDC clients, consent, access/refresh token protocol.User password database.
identity-serviceAuth orchestration; resolve Kratos session; issue internal actor assertion.Passwords or persistent Ory session state.
edge-apiPublic HTTP mapping; invoke private gRPC ports.Kratos/Hydra adapters or domain authorization.
order-serviceVerify trusted actor; ownership/business rules.Calling Kratos or trusting user-supplied headers.

2. Request flow

1. Client     -> Edge: Authorization: Bearer <Kratos session token>
2. Edge       -> Identity: ResolveSession(token, audience="order-service") over mTLS
3. Identity   -> Kratos: GET /sessions/whoami
4. Identity   -> Edge: user + Ed25519 signed actor assertion (TTL 60s)
5. Edge       -> Order: mTLS + Authorization: Bearer <actor assertion>
6. Order: verify Edge certificate, then JWT signature/iss/aud/exp
7. Order use case: actor from context; enforce ownership/business authorization
Never forward the Kratos session token past Identity. Never accept x-user-id as authority. Private networking alone does not authenticate a caller.

4. Implementation order for a new protected RPC

Step A — contract

Add the RPC/message under the owning service’s proto folder. Generate and lint:

cd common-rpc
buf generate && buf lint

Step B — domain use case

Create/extend a use case in the owner service. Receive actor through context. Check ownership in this use case, e.g. order.CustomerID == actor.UserID.

Step C — inbound gRPC adapter

Register RPC handler. Keep authentication in the existing interceptor. Handler only converts protobuf request to use case input and converts result back.

Step D — Edge outbound port and adapter

Define a capability in apps/edge-api/internal/port. Implement it in an adapter. Forward the assertion received from Identity; never reconstruct identity data.

Step E — Edge HTTP handler

Use middleware session from Gin context. Call the outbound port. Map only expected errors to HTTP. No business rule here.

Step F — prove it

Unit-test the ownership/use-case branch. Add integration coverage only for real gRPC/mTLS/assertion behavior. Add E2E only after services and Ory are started.

5. Test layout

internal/**/**_test.go       unit: one package/use case/adapter; fakes allowed
tests/integration/**_test.go integration: real boundary (gRPC, TLS, filesystem, DB)
tests/e2e/**_test.go         full process flow: Edge + Identity + Ory + Order

Current tests:

  • apps/identity-service/internal/usecase/auth/service_test.go: unit test; fake Kratos/Hydra/issuer.
  • apps/identity-service/internal/adapter/assertion/issuer_test.go: unit crypto issuance test.
  • apps/order-service/internal/identity/assertion_test.go: unit assertion verification test.
  • apps/order-service/tests/integration/mtls_test.go: integration test; real TLS listener, Edge certificate, and signed assertion.

6. Run locally, in order

# 1. Generate ignored local trust material
./deployments/compose/certs/generate.sh

# 2. Start Ory infrastructure
cd deployments/compose && docker compose up -d postgres kratos hydra

# 3. Create local config once
cp ../../apps/identity-service/properties.example.yaml ../../apps/identity-service/properties.yaml

# 4. Separate terminals from repository root
cd apps/identity-service && go run ./cmd/identity-service
cd apps/order-service && go run ./cmd/order-service
cd apps/edge-api && go run ./cmd/edge-api

# 5. Register, then save session_token from response
curl -X POST http://localhost:8080/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"Str0ngPass!1"}'

# 6. Exercise verified propagation
curl -H 'Authorization: Bearer <session_token>' \
  http://localhost:8080/auth/order-caller
Expected result: HTTP 200 with your Kratos user ID/email and caller_service: edge-api. A missing/invalid client session, mTLS identity, or assertion must fail.
